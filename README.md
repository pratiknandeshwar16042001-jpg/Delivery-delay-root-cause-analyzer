# Delivery Delay Root Cause Analyzer

A business analytics project designed to identify the root causes of project delivery delays, quantify their impact, and support earlier management intervention using Python, SQL, and Power BI.

## Project Objective

Many organisations track delayed projects, but few understand which operational factors are driving schedule slippage. This project analyses a delivery portfolio to identify delay patterns, root causes, bottleneck phases, and high-risk projects requiring action.

## Tools Used

- Python
- SQL
- Power BI
- Excel

## Dataset

This project uses a synthetic but business-realistic delivery portfolio dataset, including:

- 200 projects
- 1,200 milestones
- 1,500 issues
- resource and change request data

## Methodology

1. Created a multi-table project dataset.
2. Built a project-level master table using Python and SQL.
3. Engineered KPIs including delay days, major delay flag, risk score, and risk band.
4. Analysed delivery performance by project type, business unit, region, and phase.
5. Built a 5-page Power BI dashboard for executive reporting and action prioritisation.

## Dashboard Pages

1. Executive Overview
2. Delivery Performance
3. Root Cause Analysis
4. Phase Bottlenecks
5. Risk & Action

## Key Insights

- Scope Change was the most frequent delay driver.
- Approval Delay was the most damaging root cause by severity.
- Execution, Approval, and Signoff were the key bottleneck phases.
- IT Delivery and Transformation projects had the highest delay exposure.
- High-risk projects showed materially worse delay outcomes than the wider portfolio.

## Recommendations

- Strengthen change control to reduce scope-related disruption.
- Introduce approval SLAs for critical project decisions.
- Use risk scoring to escalate high-risk projects earlier.
- Focus governance support on bottleneck phases and high-risk project types.
- Use the dashboard as an early-warning tool rather than only a reporting tool.
